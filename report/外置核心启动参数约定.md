# 外置核心启动参数约定（launcher ⇄ core）

**适用对象**：所有由 GBAStation 拉起的外置核心 NRO —— NDS、3DS、街机、DC、PSP、PS1、Saturn、GC/Wii。

**基线**：`GBAStation` @ `299de77b`（本约定生效版本）。文中所有行号均在 `GBAStation/` 内。

**范围**：只规定**启动方向**的 argv 与两条启动通路的行为。返回方向的参数约定见本文「6. 已废弃参数」——核心跳回启动器时不携带任何参数。

---

## 1. 两条启动通路

| 通路 | 谁拉起谁 | 是否有启动器进程参与 |
|---|---|---|
| **启动器启动**（应用内选游戏 / 命令行直启） | 启动器 → 核心 | 是，启动器先排队再跳转 |
| **桌面转发器启动**（HOME 菜单图标） | 转发器 stub → 核心 | **否**，启动器从未运行 |

两条通路的 argv 不同，核心必须分别支持。

---

## 2. 启动器启动

### 2.1 argv 模板

```text
"<核心路径>" "<游戏文件路径>" --return "<启动器路径>"
```

### 2.2 组装规则

| 项 | 规则 | 出处 |
|---|---|---|
| 引号 | 所有**值**加双引号，并转义 `"` 与 `\`；`--return` 标志本身不加引号 | `src/platform/switch/NroLauncher.cpp:26-38, 114-123` |
| ROM 位 | `romPath` 为空时整个 ROM 位省略 | 同上 `:117-119` |
| `--return` | 总是附加，值取 `<平台前缀>.externalNro.returnPath`，默认 `sdmc:/switch/GBAStation.nro` | `:121-122` |
| 附加参数位 | 结构上保留 `extraArgs` 位（当前外置核心启动不使用） | `src/platform/switch/NroLauncher.hpp:8-13` |

### 2.3 前置校验（任一失败即拒绝启动并写日志）

1. `nroPath` 非空；
2. 目标 NRO 存在（`fileExistsWithSdmcAlias`：路径带或不带 `sdmc:` 前缀都接受）；
3. ROM 存在（若给出 ROM）；
4. `envHasNextLoad()` 可用。

出处：`src/platform/switch/NroLauncher.cpp:92-112`。

### 2.4 生效时机（重要）

`launchNroOnExit()` **只排队**，不立即跳转；启动器主循环退出后才由 `commitPendingNroLaunch()` 调用 `envSetNextLoad()`。

```text
StartPage / main 直启  →  launchNroOnExit()  排队
                       →  Application::quit()
                       →  main() 主循环结束
                       →  commitPendingNroLaunch() → envSetNextLoad(core, argv)   ← 真正生效
```

出处：`src/platform/switch/NroLauncher.cpp:126-171`、`src/main.cpp:536`。

### 2.5 调用点

| 场景 | 位置 |
|---|---|
| 应用内启动 NDS | `src/ui/page/StartPage.cpp:1249-1261` |
| 应用内启动 3DS | `src/ui/page/StartPage.cpp:1272-1294` |
| 应用内启动其余 6 平台 | `src/ui/page/StartPage.cpp:1296-1339` |
| 命令行直启 | `src/main.cpp:244-340` |

## 3. 桌面转发器启动

### 3.1 argv 模板

```text
"<游戏文件路径>" --exit-to-home
```

**没有** `--return`：桌面图标不需要跳回启动器，退出即回 HOME。

### 3.2 组装规则

| 项 | 规则 | 出处 |
|---|---|---|
| 真实 argv | 全部平台统一 `"<rom>" --exit-to-home` | `src/core/forwarder/ForwarderInstaller.cpp:234-239` |
| 写入位置 | 转发器 NCA 的 `/nextArgv`（`/nextNroPath` = 核心 NRO 路径） | `src/core/forwarder/ForwarderCore.cpp:977-978` |
| legacyArgs | 保持历史取值 `"<rom>" --return "<launcher>"`，**仅**用于计算旧版 title id 以删除历史安装，不参与启动 | `src/core/forwarder/ForwarderInstaller.cpp:239` |
| 固化时机 | argv 在**安装时**写死；改动后必须重新安装转发器才生效 | `ForwarderCore.cpp:1095-1099` |

### 3.3 核心不处理 `--exit-to-home` 时的行为

转发器 stub 在加载核心前把 next-load argv 置为哨兵值：

- 核心若**未**布防返回 → stub 判定「no next NRO armed」→ `selfExit()` → 回 HOME；
- 因此在桌面图标场景下，无论核心是否识别 `--exit-to-home`，结果都是退出回 HOME。识别该标志只是让核心少绕一圈。

出处：`src/core/forwarder/hbl/source/main.c:7, 302-311, 394-395, 570`。

## 4. 路径与配置键

全部默认值注册在 `src/core/common.cpp:574-590`，配置落盘 `sdmc:/GBAStation/config/config.cfg`（`src/core/constexpr.h:49, 72-79`）。

| 平台 | `<前缀>.externalNro.path` 默认值 | `returnPath` 默认值 |
|---|---|---|
| NDS | `/GBAStation/core/GBAStationNDSStub.nro` | `sdmc:/switch/GBAStation.nro` |
| 3DS | `/GBAStation/core/GBAStation3DSStub.nro` | 同上 |
| Arcade | `/GBAStation/core/GBAStationFBNeoStub.nro` | 同上 |
| Dreamcast | `/GBAStation/core/GBAStationFlycastStub.nro` | 同上 |
| PSP | `/GBAStation/core/GBAStationPPSSPPStub.nro` | 同上 |
| PS1 | `/GBAStation/core/GBAStationDuckStationStub.nro` | 同上 |
| Saturn | `/GBAStation/core/GBAStationYabaSanshiroStub.nro` | 同上 |
| Dolphin | `/GBAStation/core/GBAStationDolphinStub.nro` | 同上 |

- 配置键前缀依次为 `nds.`、`3ds.`、`arcade.`、`dc.`、`psp.`、`core.ps1.`、`saturn.`、`dolphin.`。
- 默认 NRO 路径**不带** `sdmc:` 前缀，校验时两种写法等价（`NroLauncher.cpp:50-62`）。
- **配置所有权**：启动器独占写权，核心只读；启动器不在每次启动时改写全局配置。

## 6. 已废弃参数

以下参数**不再出现在启动 argv 中，启动器也不再有对应处理**（会话/token 机制已整体移除）：

| 参数 | 原用途 | 现状 |
|---|---|---|
| `--gbastation-session <token>` | 启动器建会话并 +1 playCount | 不发送 |
| `--external-return <token>` | 核心回传 token 以结算 playTime | 不再识别（仅在 `parseDirectLaunchRom` 保留跳过分支，避免旧核心回传的 token 被当成 ROM 路径） |

核心解析到这两个参数时可直接忽略；若仍按旧约定回传 `--external-return`，不会造成统计结算，只会被跳过。

出处：`src/main.cpp:88-99`、`src/core/ExternalCoreSession.*`（已删除）。

---

## 7. 统计归属

前端**不再**做任何游玩时长/次数记账：

- `playCount` / `playTime` / `lastPlayed` 按约定由**核心自己**写入 `sdmc:/GBAStation/data/GameData_<平台>.json`（`src/core/constexpr.h:84-87`）；启动器不校验核心是否真的写了。
- 启动器侧不再产生会话文件，因此 SD 卡上遗留的 `sdmc:/GBAStation/config/external_core_session.json` 是**孤儿文件**，可手工删除。

---

## 8. 验证方法

```bash
# 1. 启动器启动：排队与提交的完整 argv（含拒绝原因）
cat /Volumes/<SD卡>/GBAStation/debug/external_core_launch.log
grep -E 'launch pending|commit ok|commit reject|launch reject' /Volumes/<SD卡>/GBAStation/debug/external_core_launch.log

# 2. 启动器是否真的被重新拉起（每次进程启动写一行，含全量 argv）
grep 'launcher entry' /Volumes/<SD卡>/GBAStation/debug/external_core_launch.log

# 3. 桌面转发器：安装的 argv、核心是否布防返回、是否 selfExit 回 HOME
cat /Volumes/<SD卡>/GBAStation/debug/forwarder.log
grep -E 'romfs: defaultNro|loadNro: entry|next-load argv untouched|selfExit' /Volumes/<SD卡>/GBAStation/debug/forwarder.log
```

日志行格式（源码固定）：

| 日志 | 格式 | 出处 |
|---|---|---|
| 排队 | `launch pending nro=%s argv=%s` | `NroLauncher.cpp:130` |
| 拒绝 | `launch reject: <原因>` | `NroLauncher.cpp:96-112` |
| 提交成功 | `commit ok nro=%s argv=%s` | `NroLauncher.cpp:169` |
| 启动器进程入口 | `launcher entry t=<epoch> argc=N argv[0]=…` | `NroLauncher.cpp:174-187` |
| 转发器默认/当前 NRO | `romfs: defaultNro=%s defaultArgv=%s`、`loadNro: entry ... nextNro=%s nextArgv=%s` | `hbl/source/main.c:297-311, 394-396` |

**注意**：`envSetNextLoad` 的 argv 由 loader 分词，其去引号行为无法从本仓库确认，需用上面第 1、2 条日志与核心侧 argv 日志现场对齐。
