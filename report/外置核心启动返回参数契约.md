# 外置核心：启动参数与返回参数契约（launcher ⇄ core）

本文梳理 GBAStation（Switch 前端）**拉起核心**与**核心返回前端**两个方向、8 个平台的
参数契约。结论均以代码为准并附 `文件:行号`；不在工作区内的核心已明确标注。

分析基线：`GBAStation` @ `7b692c25`，`GBAStation_DrasticDS` @ `5f1457a`，
`GBAStation_melonDS` / `GBAStation_3DS` / `gsnx_azahar` / `GBAStation_ppsspp` /
`gsnx_duckstation` / `yabasanshiro` 各自 HEAD。

---

## 1. 一次完整往返

```
应用内启动（前端 UI 点游戏）
  StartPage::launchExternalCoreNro / launchNdsExternalNro / launchThreeDsExternalNro
        │  登记 pending，不立即生效
        ▼
  NroLauncher::launchNroOnExit()   ← 只排队；校验 NRO/ROM 存在、envHasNextLoad()
        │
        ▼  前端主循环退出时
  main.cpp:555  commitPendingNroLaunch() → envSetNextLoad(core.nro, argv)
        │
        ▼  loader 拉起核心
  核心解析 argv（ROM / --return / --gbastation-session / --exit-to-home …）
        │
        ▼  玩家退出
  核心 envSetNextLoad(launcher, returnArgv)  → loader 拉起启动器
  启动器 main() 识别 --external-return <token> → 结算 playTime

桌面图标启动
  HOME 菜单 → 转发器标题（HBL stub）→ 读自身 romfs /nextArgv + /nextNroPath
        → 以同一 argv 模板拉起核心（内容由安装时写入的 args 决定）
```

## 2. 启动方向：前端怎么发

### 2.1 应用内启动（`NroLauncher.cpp`）

## 3. 返回方向：核心怎么回、前端怎么认

| 项 | 值 | 证据 |
|---|---|---|
| 前端唯一识别的返回参数 | `--external-return <token>` | ExternalCoreSession.cpp:146-154 |
| 识别后动作 | `finishExternalCoreSession(token)`：校验 token → `playTime += now-startedAt`（上限 7 天）→ 删会话文件 | main.cpp:396-406、ExternalCoreSession.cpp:105-144 |
| 没识别到 | **什么都不做**：会话文件残留、playTime 不结算（无兜底） | main.cpp:396-406 |
| 启动时前端发的 token | `--gbastation-session <token>`（**与返回参数名不同**） | StartPage.cpp:1337-1338、main.cpp:271-272 |

## 6. 不一致与风险清单（按影响排序）

1. **会话结算只有 PSP 能完成**：前端只认 `--external-return`，而 NDS/3DS/PS1/Drastic/melonDS/DuckStation
   都只回传引号包住的路径，token 从不回传 → `beginExternalCoreSession` 已经 +1 并写盘，
   `finishExternalCoreSession` 永不执行 → 每次库内启动残留 `external_core_session.json`，
   playTime 永久丢失。证据：ExternalCoreSession.cpp:105-154、main.cpp:396-406；
   PSP GBAStationChainload.cpp:70-72；PS1 nogui_host.cpp:257-258；3DS main.cpp:378。
2. **PSP/PS1 统计双写**（见 §5）：`platformReportsOwnStats` 应补 PSP/PS1，并核实 3DS/DC/Arcade/Dolphin。
3. **`--resume` 是死参数**：PSP 无 token 时发出（GBAStationChainload.cpp:72），前端无处理，
   只被 `-` 规则跳过 → 转发器场景（不带 token）必然走这条"无结算"分支。
4. **3DS 已把 `--gbastation-session` 标为废弃**（gsnx_azahar/docs/launch_parameters.md §6），
   而前端仍对 Arcade/DC/PSP/PS1/Dolphin 发送（StartPage.cpp:1337-1338）→ 需统一：
   要么核心都实现 token 回传，要么前端停止发会话。
5. **NDS 应用内启动忽略配置键**：NRO 路径硬编码（StartPage.cpp:1255），与 `nds.externalNro.path` 不一致。
6. **`parseDirectLaunchRom` 会把 `--gbastation-session` 的值当 ROM**：该标志被跳过，但其后
   token 不以 `-`/`.nro` 开头 → 若核心原样回显启动 argv 就会被误判（main.cpp:107-112）。
7. **返回目标存在性检查不统一**：Saturn/3DS/PSP 有检查（Saturn 存在检查、3DS `stat`、PSP 三级回退），
   NDS/PS1 无检查；`envSetNextLoad` 返回码在 PSP/Saturn 之外多被忽略。
8. **返回 argv 引号规则不统一**：3DS/NDS/PS1/melonDS 加引号，PSP/Saturn 不加。
9. **`--exit-to-home` 只发给 NDS/3DS**，但 PS1 也实现了该分支（nogui_host.cpp:1390-1395）→ 死分支；
   桌面图标对 NDS/3DS 退 HOME、对其它平台回启动器，语义不统一。
10. **DC 扩展名拦截两处不一致**：StartPage 拦 `.iso`（StartPage.cpp:1310），main.cpp 只拦 `.zip/.7z`（main.cpp:251）。
11. **Arcade/DC/Dolphin 核心源码不在工作区**，无法核对核心侧参数与是否自记统计。

## 7. 建议的收敛方向

1. **统一"是否由前端记账"**：把 PSP/PS1（确认自记）加入 `platformReportsOwnStats`；
   对不自记的平台，要求核心回传 `--external-return <token>`。3DS 文档已把该机制标为废弃，
   所以先决定是"全面启用"还是"全面废弃"。
2. **若决定废弃会话机制**：前端停止生成/发送 `--gbastation-session`，改为各核心自记
   （Saturn 模式），并清理残留会话文件；否则给 `finishExternalCoreSession` 增加兜底
   （按 `startedAt` 结算或丢弃残留会话）。
3. **统一返回参数**：把"返回 NRO 路径 + 可选 token"写进一份共享契约文档
   （可参考 `gsnx_azahar/docs/launch_parameters.md`），所有核心遵循同一引号规则与存在性检查。
4. **NDS 应用内启动改读 `nds.externalNro.path`**，与其它平台一致。
5. **`parseDirectLaunchRom` 显式消费 `--gbastation-session <value>`**，避免 token 被当 ROM。

目标（用户决议）：启动只传 ROM 路径；返回启动器时不携带任何参数（只把启动器路径作为
下一个 NRO 的 argv[0]）。以下为逐处核对结果。

### 9.1 启动时多传了参数（必须去掉）

| # | 位置 | 现在多传的 | 备注 |
|---|---|---|---|
| A1 | `NroLauncher.cpp:121-122` | ` --return "<returnPath>"` | 应用内启动统一附加，所有平台都带 |
| A2 | `NroLauncher.cpp:119-120` + `StartPage.cpp:1337-1338` + `main.cpp:271-272` | `"--gbastation-session" "<token>"` | Arcade/DC/PSP/PS1/Dolphin 会带 |
| A3 | `StartPage.cpp:1250-1271`（NDS）、`1273-1295`（3DS）、`1297-1355`（通用） | 调用处仍传 `returnNroPath` | 三个启动函数都要改 |

| # | 位置 | 现状 | 去掉参数后的后果 |
|---|---|---|---|

| C2 | `gsnx_duckstation/src/duckstation-nogui/nogui_host.cpp:232` | `s_switch_return_to_nro = false` 默认 | 没有 `--return` 就不布防 → 不回启动器；应默认 `true` + 默认路径 |

### 9.4 连带影响：统计（playCount/playTime）怎么办

没有 token 通道后，前端必须在**不依赖参数**的前提下记账，两条路：

1. **核心自记（Saturn 模式，最干净）**：所有核心写各自 `GameData_*.json` 的
   playCount/playTime/lastPlayed，前端彻底删掉会话机制与 `platformReportsOwnStats`。
   现状：Saturn / NDS(Drastic、melonDS) / PSP / PS1 / 3DS(citra) 已自记；
   **3DS(azahar) 未实现自记**，Arcade / DC / Dolphin 未知（源码不在工作区）。
2. **前端无参数记账（改动最小，推荐作为过渡）**：启动核心前把 `{romPath, startedAt}`
   写进单槽 `external_core_session.json`；**下次启动时**只要发现该文件存在，就按
   `startedAt` 补记 playTime 并删除。因为"启动器被重新拉起"本身就是返回信号，
   完全不需要返回参数。注意崩溃/断电会留下记录，需要上限钳制（现有 7 天上限可用，
   建议再收紧到单次游玩上限）。

### 9.5 结论

- **启动方向**：前端 6 处（A1-A6）需要改成"只传 ROM 路径"；其中 A6（CIA 安装模式）
  不能只靠 argv，需换通道。
