# GBAStation 外置核心接入必做清单

面向对象：任何要被 GBAStation 启动的"外置核心" NRO（现有 NDS/melonDS、PSP/PPSSPP、3DS、DC/Flycast、PS1/DuckStation、Arcade/FBNeo、GC-Wii/Dolphin、**Saturn/YabaSanshiro**）。

依据：两套已落地的实现对照 ——

* `GBAStation_melonDS/nds_stub/**`（薄 glue，单体 runtime）
* `GBAStation_ppsspp/GBAStation/**`（厚 glue，可复用 `CoreRuntime` 框架 + 资源安装 + RetroAchievements）
* 前端契约来自 `GBAStation/src/**`

用法：P0 全部做完核心才能"被前端正常拉起、正常运行、正常放回"；P1 决定数据正确性与体验；P2 是能力扩展。每项都给了验收方法和参考实现。

## A. P0 —— 不做就跑不起来

- [ ] **A1 程序入口与 argv 解析**
  - 支持 `--return <nro>`（吃掉下一个参数，非空才覆盖）。
  - 支持 `--gbastation-session <token>`（吃掉下一个参数；**即使暂时不用也要吃掉**，否则 token 会被当 ROM）。
  - 跳过其余 `--*` 与 `*.nro`；**第一个其它位置参数 = 内容路径**，无则打印 Usage 并以非 0 退出。
  - 建议同时接受 `--exit-to-home`（前端 forwarder 会对 NDS/3DS 传它；见下）。
  - 参考：PPSSPP `GBAStation_ppsspp/GBAStation/GBAStationMain.cpp:56-84`（最完整）；melonDS `GBAStation_melonDS/nds_stub/src/NdsDekoStubMain.cpp:211-249`（缺 `--gbastation-session`，是已知短板）。
  - 验收：`hbmenu` 直接启动无参数时给出 Usage；带 `--return` 时能拿到返回路径；`argv` 全量写日志。

- [ ] **A2 内容加载**
  - 用 argv 传入的 ROM/镜像路径直接加载，**不要**弹自己的文件浏览器当主路径。
  - 存档路径优先取 GameDB 的 `savePath`，为空时回退 `sdmc:/GBAStation/saves/<badge>/<stem>/`。
  - 参考：melonDS `NdsDekoRuntime.cpp:2626,2684`。
  - 验收：从游戏库启动能直接进游戏；存档落在 GameDB 指定目录。

- [ ] **A3 返回前端（chainload）**
  - 退出时 `envSetNextLoad(<returnNro>, "<returnNro> --external-return <token>")`；**没有 token 时降级为只传路径**（前端两者都能吃）。
  - 返回前先做目标存在性检查，失败则回退候选 `sdmc:/switch/GBAStation.nro` → `sdmc:/GBAStation/GBAStation.nro`，都不在就跳过链回。
  - 只有"用户主动退出"才链回；初始化失败/崩溃/被动结束不要链回（否则会盖掉真实错误）。
  - 参考：PPSSPP `GBAStationChainload.cpp:25-81`（存在性检查 + 双候选 + token）；melonDS `NdsDekoRuntime.cpp:2039-2058`（无检查、无 token）。
  - ⚠️ 前端只在 `--return` 存在时才会被链回，因此**独立从 hbmenu 启动时不要链回**。
  - 验收：退出游戏后回到 GBAStation；把 `.nro` 改名后退出不掉进黑屏。

- [ ] **A4 读取 `config.cfg`（全局 + 核心设置）**
  - 路径先试 `sdmc:/GBAStation/config/config.cfg`，再试 `/GBAStation/config/config.cfg`。
  - 解析 `key=<type>|<payload>`：剥掉 `type|`，`s` 类型再反转义 `\\`/`\,`/`\|`。
  - 至少消费：`core.<前缀>.*`、`<前缀>handle.*`、`<前缀>hotkey.*`、`fastforward.*`、`save.*`、`display.showFps`。
  - 不要读核心自己的 ini/jsonc 当唯一来源（PPSSPP 的 `ppsspp.ini` 在宿主路径下根本不会写，`searchPath_` 未设置）。
  - 参考：melonDS `NdsDekoRuntime.cpp:1630-1649,1814-1853`；PPSSPP `PpssppRuntime.cpp:246-313`。
  - 验收：改前端设置后重启核心，行为随之改变。

- [ ] **A5 读取 `GameData_<平台>.json`（每游戏配置）**
  - 数组、按 `path` 匹配；比较前归一化（`\`→`/`、去 `sdmc:` 前缀、折叠前导 `//`）。
  - 至少读：`savePath`、`title`、`playCount`/`playTime`/`lastPlayed`、`overlayEnabled`/`overlayPath`、`shaderEnabled`/`shaderPath`，以及画面字段。
  - 参考：melonDS `NdsDekoStubMain.cpp:162-201`；PPSSPP `PpssppRuntime.cpp:1657-1700`。
  - 验收：同一 ROM 在不同目录/不同 `sdmc:` 写法下都能命中同一条记录。

- [ ] **A6 存档与即时档落盘**
  - 退出/复位/存即时档前必须 flush 卡带/记忆卡存档。
  - 即时档先写 `.tmp` 再 rename（melonDS 做法），避免半截文件被当成有效档。
  - 参考：melonDS `NdsDekoRuntime.cpp:1518-1546,3755`。
  - 验收：游戏中强制关机后存档仍在；损坏的即时档被拒绝而不是崩。

- [ ] **A7 生命周期与主循环**
  - 主循环条件用 `appletMainLoop()`；建议调用 `appletLockExit()`（PPSSPP `GBAStationMain.cpp:142`，melonDS 漏了）。
  - 退出顺序：停音频线程 → flush 存档 → 释放渲染资源 → `romfsExit()` → 最后才 `envSetNextLoad`。
  - 验收：TV/掌机模式切换、休眠唤醒不崩；退出无残留线程。

## B. P1 —— 数据正确性与体验

- [ ] **B1 写回 `config.cfg` 时保持类型**
  - 字符串写 `s|`，int 写 `i|`，float 写 `f|`，bool 用 `i|`。
  - ⚠️ 反面教材：PPSSPP 一律用 `s|` 回写（`PpssppRuntime.cpp:2111-2155`），导致前端按 float 读的 `fastforward.multiplier`、按 int 读的 `auto_frameskip`/`fast_memory` 全部失效回落默认值。melonDS 的类型是对的（`NdsDekoRuntime.cpp:1886-1921`）。

- [ ] **B2 GameDB 原子写**
  - 用 `写 .tmp → rename`（FAT 不支持覆盖时保留 `.bak` 回滚），不要直接 `ofstream(path, trunc)`。
  - ⚠️ 反面教材：melonDS 有 **7 处** GameDB 直接截断重写（`GBAStation_melonDS/nds_stub/src/NdsDekoRuntime.cpp:438,546,631,702,772,839,908`），写盘中断会毁掉整个 NDS 游戏库；PPSSPP 的 `WriteGameDbAtomically` 是正确做法（`PpssppRuntime.cpp:1355-1396`）。

- [ ] **B3 决定 playCount/playTime 的责任归属（二选一，别都做）**
  - **路线 1（推荐，走会话）**：回传 `--external-return <token>`，**自己不要**再 `+1 playCount`/累计 `playTime`（前端 `beginExternalCoreSession` 已 +1，`finishExternalCoreSession` 会补 playTime）。
  - **路线 2（不走会话）**：自己维护 `playCount+1` 与 `playTime`/`lastPlayed`（melonDS 路线，`NdsDekoRuntime.cpp:395-461,503-570`），但要接受前端不计时。
  - ⚠️ 反面教材：PPSSPP **两条都做** → playCount/playTime 双计数。

- [ ] **B4 每游戏设置回写 + 同步 + `noSync`**
  - 菜单改画面/遮罩/滤镜后写回本游戏记录；提供"同步到同平台其它游戏"时**跳过 `noSync == 1`** 的游戏。
  - 回写字段名与前端一致（沿用共享 schema：`displayMode`/`ndsScreenLayout`/`ndsInternalResolution`/`integerAspectRatio`/`customScale`/`customOffsetX,Y`、`overlayEnabled`/`overlayPath`、`shaderEnabled`/`shaderPath`/`shaderParaNames/Values`、`noSync`）。
  - 参考：melonDS `NdsDekoRuntime.cpp:572-933`（含 `noSync` 跳过）。

- [ ] **B5 语言跟随前端 `UI.language`**
  - 从 `config.cfg` 读 `UI.language`，值形如 `s|zh-CN`：**先剥 `s|` 类型前缀，再剥可能存在的双引号**。
  - ⚠️ 反面教材：melonDS `NdsLanguage.hpp:79-82` 只剥引号不剥 `s|` → 英/日界面永远显示中文。正确实现见 PPSSPP `GBAStationTranslationManager.cpp:116-138`（并支持 `general.jsonc` 回退与硬编码兜底）。

- [ ] **B6 遮罩 PNG（前端语义）**
  - 前端对每个平台都写 `overlayEnabled`/`overlayPath`（全局键 `display.overlay.<平台>Path`），期望核心把 PNG 叠在画面之上。
  - 参考实现：melonDS `NdsGameLayer.cpp:988-997` + `NdsDekoRuntime.cpp:2736-2784`；PPSSPP **未实现**（它的 "Overlay" 是 ImGui 菜单，别被文件名误导）。

- [ ] **B7 输入映射与热键**
  - 消费 `<前缀>handle.*`（combo 用 `+`、多绑定用 `|`）与 `<前缀>hotkey.*`（菜单/快进/存/读/截图/静音/暂停/复位）。
  - 默认值要与前端一致，否则"恢复默认"与首次运行体验不一致。
  - ⚠️ 前端的一个坑：通用默认值先写入、平台专属默认值后写入，而 `SetDefault` 只在键不存在时生效（`GBAStation/src/core/ConfigManager.cpp:145-155`），所以**平台专属默认值只对"恢复默认"生效**，首次运行拿到的是通用值。若你的核心依赖某个特定默认，请同时在前端侧调整或不要依赖。

- [ ] **B8 存/读档槽与缩略图**
  - 建议 10 槽；缩略图 `<state>.png`，尺寸 256×384 级别。
  - 验收：菜单里能看到缩略图、能删除槽位。

- [ ] **B9 快进**
  - 读 `fastforward.multiplier`（float）、`fastforward.mode`、`fastforward.enabled`、`fastforward.mute`、`turbo.rate`。
  - 音频侧注意：快进时一个调度片可能模拟多帧，FIFO 要够大（melonDS 把 SPU 缓冲从 4096 提到 16384 帧，`GBAStation_melonDS/src/SPU.cpp:66`）。

## C. P2 —— 能力扩展（可选）

- [ ] **C1 资源安装器（romfs → SD）+ 版本标记**
  - 若核心需要把 shader/flash0/字体等资源落到 SD，用"版本标记 + 哨兵文件"做幂等（PPSSPP `GBAStationAssetInstaller.cpp:19-272`，marker `ppsspp-GBAStation-assets-v3` + 5 个哨兵）。
  - ⚠️ 如果沿用 SD 回退路径，务必与实际安装布局一致：PPSSPP 的多条回退（`PSP/assets/ui/...`、`PSP/assets/ra.svg`、`PSP/fonts/...`）因安装到 `PSP/ui`、且排除 `ra.svg` 而**永不命中**；melonDS 的 `sdmc:/GBAStation/resources/...` 回退同样死路（前端从不安装 `resources/`）。
- [ ] **C2 RetroAchievements**
  - 前端**没有**任何 RA 代码，RA 完全是核心侧能力；账号/开关建议放 `sdmc:/GBAStation/config/accounts.jsonc`（PPSSPP 约定，键 `ra_enabled`/`ra_username`/`ra_password`/`ra_token`/`ra_hardcore_mode`/`ra_alert_position`）。
  - ⚠️ melonDS 在 CMake 里把 RA/rcheevos 整个剔除了 → 相对接入前的 `melonDS.nro` 是**功能回退**。新核心若要 RA，直接抄 PPSSPP 的 `GBAStationRetroAchievements.cpp`。
- [ ] **C3 日志规范**
  - 建议统一到 `sdmc:/GBAStation/debug/<core>_stub.log`（PPSSPP 约定）；melonDS 用的是 `sdmc:/GBAStation/log/NdsDekoStub.log`，两边不一致。
  - 日志要能在"启动失败的第一次运行"里定位问题（记 argv、ROM、SavePath、BIOS 路径、关键初始化返回值）。
- [ ] **C4 可复用宿主框架**
  - 若后续还要接多个核心，把 PPSSPP 的 `CoreRuntime` 接口（`GBAStationMain.h:26-41`：`Configure/Initialize/LoadContent/HandleInput/RunFrame/RenderFrame/ShouldExit/ShouldChainloadLauncher/RequestExit/Shutdown`）抽出来复用，比 melonDS 的单体 `RunDekoRuntime` 更省事。

## D. 实机验收清单（每个核心都跑一遍）

- [ ] 游戏库启动 → 进游戏 → 菜单退出 → 回到 GBAStation（且**不是**掉回 Home）
- [ ] hbmenu 直接启动（无 `--return`）→ 退出时**不**链回
- [ ] 把返回的 `.nro` 改名 → 退出时优雅降级，不黑屏
- [ ] `GameData_<平台>.json` 里 `playCount`/`playTime`/`lastPlayed` 只 +1 一次（不能双计数、也不能一直为 0）
- [ ] 改前端核心设置 → 重启核心后生效；核心内改设置 → 前端/DB 能看到
- [ ] 前端语言切到 en-US → 核心界面跟着变英文（这条最容易漏）
- [ ] 存档/即时档在强制关机后仍可读
- [ ] 游戏库 JSON 在反复进出游戏后没有损坏、没有丢记录
- [ ] 反复进出游戏 20 次无显存/内存泄漏、无残留线程

## E. 反面清单（两个参考实现的已知坑，别照抄）

1. `config.cfg` 回写一律用 `s|` → bool/float 键被污染（PPSSPP）。
2. GameDB 直接截断重写（melonDS，8 处）。
3. `UI.language` 不剥 `s|` → 语言永远回落中文（melonDS）。
4. playCount/playTime 双计数（PPSSPP）。
5. `--gbastation-session` 不识别 → token 被当 ROM（melonDS，当前靠前端不传该参数侥幸不炸）。
6. 返回时不检查 NRO 是否存在、无候选回退（melonDS）。
7. 初始化失败/powerdown 路径不回 launcher（两家都有类似的 early-return）。
8. 声明了却不使用的死代码/占位：melonDS 的 `ShouldUseDekoRuntime`、`nds_stub_software.flag`；PPSSPP 的 `PlayUiSound`、`graphicsHost` 对象、`regcomp/regexec` 假实现。

## F. 前端侧可能需要同步的改动（若核心能力要生效）

- [ ] `nds.externalNro.path` 设置了但 `StartPage.cpp:1255` 硬编码路径（NDS 专用启动函数绕过了该键）。
- [ ] 平台专属热键默认值被通用默认值抢先（见 B7）。

## G. Saturn / YabaSanshiro 专用落地对照

前端已就绪的部分（无需改前端）：

| 项 | 值 |
|---|---|
| 平台 id / 数据库 | `EmuSaturn = 13` / `GameData_Saturn.json` |
| 核心路径键 | `saturn.externalNro.path`（默认 `/GBAStation/core/GBAStationYabaSanshiroStub.nro`） |
| 返回路径键 | `saturn.externalNro.returnPath`（默认 `sdmc:/switch/GBAStation.nro`） |
| 启动 | `StartPage.cpp:1575-1582, 1699-1707` → 带 `--gbastation-session` + `--return` |
| 核心设置 | `core.saturn.*` 共 18 项，见 `SettingPage.cpp:3466-3594` |
| 按键映射 | `saturn.` 前缀，a/b/c/x/y/z/l/r 换算见 `InputMappingDefaults.hpp:296-310` |
| 热键 | `saturn.handle.fastforward`、`saturn.hotkey.{menu,quicksave,quickload}.pad` |
| 存档目录 | `sdmc:/GBAStation/saves/Saturn/<stem>/` |
| 扫描扩展名 | `cue/bin/iso/chd/mds/m3u/ccd`（`DataManagementPage.cpp:1849`） |
| 前端不做的 | 无 Saturn BIOS 选择器（只有 HLE 开关）；`platformOverlayKey/ShaderKey` 对 Saturn 返回空 → 遮罩/滤镜由核心自理 |

核心侧现状与差距（`yabasanshiro/yabause/src`，快速抽查）：

- [x] 已能消费 18 个 `core.saturn.*`（`gbastation/Settings.cpp`）
- [ ] `main(argc, argv)` **未引用 argv** → 拿不到 ROM 路径（P0-A1/A2）
- [ ] 无 `envSetNextLoad` / 无 `--external-return` → 无法按 A3 返回，前端会话永远不结算（P0-A3、P1-B3）
- [ ] 未见 `GameData_Saturn.json` 读写 → 每游戏画面/遮罩/存档路径无法生效（P0-A5、P1-B4）
- [ ] 未见 `config.cfg` 的 `saturn.handle.*` / `hotkey.*` 消费 → 按键映射页无效（P1-B7）
- [ ] 未见 Saturn BIOS 路径读取约定（前端只有 HLE 开关，核心需自行定 `core.saturn.biosPath`）

建议顺序：A1 → A2 → A3（先能跑通一个回合）→ A5 → B3 → B7 → B4 → B5/B6 → 其余。
