RetroArch 的“金手指（Cheats）”在源码里其实分成 **前端UI + 文件管理 + 核心接口 + 数据库** 几块，不是在单一文件夹里。

下面给你按“真正开发时会用到的源码位置”拆开讲：

---

# 一、最核心的 Cheats 模块（重点）

### 📁 1. frontend/menu（菜单UI入口）

金手指菜单入口在这里：

```
/menu/
    menu_cbs_cheats.c
    menu_entries_cheats.c
    menu_driver.c
```

作用：

* “Cheats”菜单显示
* 加载/选择 cheat 文件
* UI操作逻辑（开关、应用）

👉 你在 RetroArch 菜单里看到的 Cheats 页面就在这里生成

---

# 二、Cheat 逻辑核心（真正执行层）

### 📁 2. core-level cheat system

真正处理 cheat 加载、解析、应用的核心代码：

```
/cheat_manager.c
/cheat_manager.h
```

这个是最重要的文件之一。

功能包括：

* 读取 `.cht` 文件
* 解析 cheat 条目
* 管理 enable/disable
* 应用 cheat 到 core memory

---

# 三、cheat 文件解析（.cht 格式）

### 📁 3. file parsing layer

```
/libretro-common/formats/cheats/
```

常见文件：

```
cheat.c
cheat.h
```

作用：

* 解析 `.cht` 文件格式
* 解析 GameShark / ActionReplay 等结构
* 转换成内部结构体

# 五、核心如何执行 cheat（非常关键）

### 📁 5. libretro API 交互

```
/libretro/
```

关键点：

RetroArch 本身不改内存，它是通过：

```c
retro_cheat_reset()
retro_cheat_set()
```

这些 API 调 core：

* core 自己决定是否支持 cheat
* RetroArch 只是“转发器”

---

# 六、不同 core 的 cheat 支持差异

在源码里你会看到：

```
/cores/
```

但更关键的是：

👉 每个 core 自己实现：

```c
retro_set_cheat_callback()
```

有些 core：

* 支持 RetroArch cheat（.cht）
* 有些只支持 native cheat（比如 PCSX2 / FBNeo）

---

# 七、总结（你最关心的结构）

一句话结构图：

```
RetroArch Cheats
│
├── UI层
│   /menu/menu_cbs_cheats.c
│
├── 管理层（核心）
│   cheat_manager.c
│
├── 解析层
│   libretro-common/formats/cheats/
│
├── 数据库
│   libretro-database/cht/
│
└── 执行层
    libretro API → core
```
